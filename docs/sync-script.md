# 同步腳本設計

把本地履歷資料同步到求職平台的編輯頁。目前完成 104 的工作經驗和自傳（2026-11-07 實測通過，見「驗證紀錄」），接著擴充到其他區塊和 CakeResume、Yourator。使用方式見 `README.md`。**LinkedIn 永遠不在範圍內**（見 `CLAUDE.md`）。

## 流程

1. 使用者執行 `npm run sync -- 104`，腳本把本地資料複製進擴充功能，並用使用者平常的 Chrome 打開履歷編輯頁。
2. 使用者自己登入（104 要手機驗證碼），進到編輯頁，右側出現同步面板。
3. 使用者在面板上按「比對」。沒有打開任何表單時，清單畫面就顯示所有已填的內容，腳本一次讀完整頁，與本地資料比對。
4. 面板依區塊列出差異（頁面值 vs 本地值），頁面上對應的清單項目加黃框。多筆區塊另外列出「本地有、頁面沒有」和「頁面有、本地沒有」的項目。
5. 使用者對有差異的那一筆按「打開並同步」，腳本 hover 該卡片、點「編輯」打開表單；對「本地有、頁面沒有」的項目按「新增到頁面」，腳本點「新增」打開空白表單。一次只能打開一筆。
6. 表單打開後，面板改列這一筆的欄位差異。使用者勾選要同步的欄位，按「同步選取的」一次寫入，或在單一欄位上按「同步這筆」。寫入一律以本地資料為準。
7. 寫入後欄位改成綠框，面板標記「已更改，請按儲存」。
8. 使用者自己檢查並按「儲存」。表單關閉後，面板自動重新比對整頁，再處理下一筆。

**腳本會點的按鈕只有「編輯」和「新增」**，而且都要使用者在面板上要求才點。腳本不點儲存、送出、刪除或取消。

## 資料來源

- `output/<平台>.<zh|en>.json`：由 `/resume-sync` 產出，內容已依規格的字數上限改寫，鍵是規格「編輯方式」表的欄位 id。範例：

  ```json
  {
    "platform": "104",
    "lang": "zh",
    "dataCommit": "5afd614",
    "fields": {
      "bio.zh": "具設計背景的前端工程師……",
      "work": [
        {
          "match": { "name": "某公司", "startDate": "2023-03" },
          "work.name": "某公司",
          "work.position": "前端工程師",
          "work.start": { "year": 2023, "month": 3 },
          "work.end": null,
          "work.description": "- 獨立開發……",
          "work.skills": ["JavaScript", "VueJS"]
        }
      ]
    }
  }
  ```

- `private.json`：私密欄位（電話、生日、兵役等），放在 repo 根目錄但列入 `.gitignore`，格式同上的 `fields`。第一版用不到，先建立 `.gitignore` 規則即可。
- 一頁可能同時有中英文欄位（104 自傳），腳本依欄位 id 的語言後綴讀取對應的 JSON。

## 多筆區塊的對應

104 的語文能力、學歷、工作經驗、專長是多筆區塊，一次只能打開一筆編輯；要新增一筆，必須先按該區塊的「新增」才會出現空白表單。其他平台開始實作時，再確認是否相同。

- **一次一筆**：寫入只針對目前打開的那一筆。面板顯示「目前編輯：第幾筆／對應本地哪一筆」，使用者按儲存後，再打開下一筆。
- **對應方式**：用 `match`（工作經驗是公司名稱＋開始年月；其他區塊的鍵在實作時定）找出本地對應的那一筆。找不到或有多筆符合時，面板顯示下拉選單讓使用者選。
- **空白表單**：如果使用者自己按了「新增」，打開的空白表單對不到任何本地資料，面板會列出「本地有、頁面沒有」的項目，讓使用者選要填哪一筆。
- **整頁清單比對**：表單沒打開時，腳本讀取清單畫面，每一筆分成三種狀態：本地有、頁面沒有（可以「新增到頁面」）；頁面有、本地沒有（只提醒，腳本不刪除）；兩邊都有（列出差異，可以「打開並同步」）。清單畫面的 selector 見 `specs/104.md`。
- **打開表單由腳本按**：「編輯」要先 hover 卡片才會出現，腳本照 `specs/104.md` 的「區塊按鈕與清單」表操作。已經有表單打開時，不能再打開另一筆，要先處理完目前那一筆。

## 比對規則

- 文字：去掉頭尾空白、把連續空白壓成一個再比對。
- 富文本：取純文字後套用上面的規則，忽略 HTML 標籤差異。
- 標籤：視為集合比對，順序不同不算差異。
- 日期：比對年和月。
- 本地值超過字數上限時，不允許同步，並在面板上標 ⚠️。

## 寫入方式

每個欄位的寫入方式記在 `specs/<平台>.md` 的「編輯方式」表，類型如下：

| 寫入方式 | 做法 |
|---|---|
| `input` | 用原生 value setter 設值，再觸發 `input` 和 `change` 事件，讓框架（Vue／React）收到變更 |
| `quill` | 用 Quill 實例 `setText(text, 'user')` 寫入。104 的實例在 `.ql-container.__quill`，儲存後有生效，存成 `<p>` 段落（已驗證） |
| `dropdown` | 點開自訂下拉，再點文字相符的選項 |
| `tags` | 先刪除多出的標籤（點標籤上的 ×），再在輸入框輸入並按 Enter 新增缺少的 |
| `checkbox` | 狀態不同時點一下 |

## 面板

- 固定在頁面右側，拖曳橘色標題列可以移動，按「－」收合；樣式用 shadow DOM 隔離，不影響頁面。
- 標題顯示版本號（`104.page.js` 的 `VERSION`），改了程式就要加一，用來確認擴充功能已經重新載入。
- 清單模式：依區塊列出差異、「對應本地：○○」、「本地有、頁面沒有」（新增到頁面）、「頁面有、本地沒有」（只提醒）。
- 表單模式：列出這一筆的欄位差異，可以全選、勾選後「同步選取的」，或逐筆「同步這筆」；本地值超過字數上限的不能同步。
- 104 的必填檢查訊息（`.form-element-inputbox__valid`）會用紅字列在面板上，例如「職務類別：請填寫」。
- 框線：黃色是有差異，綠色是已寫入、等待儲存，灰色是頁面有、本地沒有。
- 頁面上的表單打開或關閉時，面板會自動重新比對。
- 除錯訊息在該頁 DevTools Console，開頭是 `[resume-sync]`。抓面板全文：`copy(document.getElementById('resume-sync-panel').shadowRoot.querySelector('.p').innerText)`。

## 技術選擇

- **Chrome 擴充功能（未封裝，MV3）**，放在 `sync/extension/`，在使用者平常用的 Chrome 執行。使用者在 `chrome://extensions` 開啟開發人員模式，「載入未封裝項目」選 `sync/extension/`，只要做一次。
- 不用 Playwright：2026-11-07 驗證過，104 會把 Playwright 開的 Chrome 擋在 104 自己的錯誤頁，連首頁都打不開。不要用繞過偵測的方式處理。
- `npm run sync -- <平台>`：把 `output/<平台>.<zh|en>.json` 和 `private.json` 複製到 `sync/extension/data/`（列入 `.gitignore`），再用 `open -a "Google Chrome"` 打開平台編輯頁。
- 擴充功能分三個檔：
  - `bg.js`：service worker，讀取 `data/` 裡的 JSON。
  - `bridge.js`：隔離環境的 content script，轉送資料。
  - `104.page.js`：以 `world: "MAIN"` 執行的面板、比對與寫入。必須跑在頁面環境，才讀得到 `.ql-container.__quill`。
- 頁面環境和隔離環境之間用 `window.postMessage` 傳資料。每次按「比對」都會重讀，所以改了 `output/` 後重跑 `npm run sync` 就好，不用重新載入擴充功能。
- 權限只開 `https://pda.104.com.tw/*`。

## 驗收

- 打開一筆工作經驗，按「比對」，差異欄位有黃框，面板列出的值和頁面一致。
- 同步選取的欄位後，頁面上的值與本地值一致，欄位變成綠框；腳本沒有點過「儲存」。
- 使用者按儲存後重新整理頁面、再比對，該筆沒有差異。
- 本地值超過字數上限時，同步按鈕不能按。
